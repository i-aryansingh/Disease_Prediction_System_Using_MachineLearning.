# Symptom-Based Disease Prediction System (SBDPS)

A web app where users pick symptoms from a structured list and get a **preliminary** Random Forest prediction (top 3 diseases with model-generated scores).
Stack: HTML/CSS/JavaScript, FastAPI, scikit-learn, pandas/NumPy, joblib. No Flask, NLP, desktop or mobile app.

> **Academic demonstration only. Not a medical diagnosis.**

## Important: dataset status

The original dataset was **not supplied**, so this project ships a **synthetic demo dataset** (15 diseases, 44 symptoms) generated by `backend/generate_demo_dataset.py`. It is not real patient data and not medically validated. Metrics shown in the app are genuinely computed on its held-out test split, but because the data is synthetic they say nothing about real-world accuracy.

To use your real dataset:
1. Save it as `dataset/disease_symptoms.csv`: one column per symptom (values 0/1, e.g. `skin_rash`) and a final label column named `prognosis`.
2. Delete `dataset/dataset_info.json` (it marks the data as demo).
3. Retrain (step 4 below). Disease and symptom counts on the dashboard come from the data. The paper's 42 diseases / 132 symptoms appear only if your CSV contains them.

## Windows setup (VS Code terminal, PowerShell)

```powershell
cd SBDPS
python -m venv venv
venv\Scripts\activate
pip install -r backend\requirements.txt
python backend\train_model.py
uvicorn backend.main:app --reload
```
Open http://127.0.0.1:8000 in your browser. API docs: http://127.0.0.1:8000/docs

If PowerShell blocks activation, run `Set-ExecutionPolicy -Scope Process Bypass` first.

Optional: `python backend\generate_demo_dataset.py` regenerates the demo data. Run tests with `pytest tests -v`.

## Voice commands

Click **Voice** in the navigation bar (Chrome or Edge; the button is disabled in browsers without speech recognition) and allow the microphone. Commands are a fixed set, and symptom names must match the list exactly; there is no free-text or NLP symptom extraction.

| Say | Effect |
|---|---|
| "select fever" / "select fever and cough" | Adds symptoms (Symptoms page) |
| "remove fever" | Removes a symptom |
| "search headache" / "clear search" | Filters the list |
| "reset" | Clears the form |
| "predict" | Submits the selection |
| "read symptoms" / "read result" | Reads the selection or the prediction aloud |
| "go home", "check symptoms", "open dashboard" | Navigation |
| "help", "stop listening" | Command list / turn off |

Privacy: Chrome and Edge send microphone audio to the browser vendor's online speech service, so voice needs an internet connection. The app itself never receives or stores audio, only the text of the symptoms you submit. Voice stops when you navigate to another page; click **Voice** again to resume. Language is English (en-IN).
Test the command parser (no microphone needed): `node tests/test_voice.js`.

## API

| Endpoint | Purpose |
|---|---|
| `GET /api/health` | Backend status and whether the model is loaded |
| `GET /api/symptoms` | Supported symptoms (`key`, `label`) |
| `POST /api/predict` | Body `{"symptoms": ["high_fever", "chills"]}`; returns top-3 predictions |
| `GET /api/model-info` | Dataset counts and evaluation metrics |

Errors: 400 empty/unknown symptoms, 422 malformed body, 503 model not trained, 500 generic (details are logged server-side only).

## How the frontend talks to the backend

FastAPI serves both the API and the static `frontend/` folder from one origin, so the JavaScript uses relative URLs (`/api/...`).
- `symptoms.js` loads `/api/symptoms`, builds the checkbox list, and on **Predict** sends `POST /api/predict` with JSON.
- The response is kept in the browser's `sessionStorage` (never stored on the server, cleared when the tab closes) and `results.html` renders it using `textContent` only.
- `main.js` fills the dashboard from `/api/model-info`.

## How the model turns symptoms into predictions

1. **Training** (`train_model.py`): the CSV is cleaned (missing symptom cells become 0, values become 0/1). The data is split 80/20, stratified, seed 42, *before* anything else touches it. A 200-tree Random Forest is fit on the training part only. Class imbalance is handled with `class_weight="balanced_subsample"` (no synthetic oversampling, so nothing can leak into the test set).
2. **Evaluation**: accuracy and weighted precision/recall/F1 on the test split are saved to `models/metadata.json`.
3. **Saving**: `random_forest.joblib` stores the model together with the ordered feature list.
4. **Prediction** (`predict.py`): selected symptom names are normalised and validated against that feature list, then turned into a 0/1 row whose columns follow the training order. `predict_proba` gives each disease's score (the share of tree votes); the top three are returned. These scores are estimates, not calibrated medical probabilities.
